================================================================================
3DOO — WORK NOT INCLUDED IN THE MVP
================================================================================

The MVP covers the spec's "definition of done for the first usable release":
create a primitive, enter edit mode, select verts/edges/faces, transform,
extrude, inset, bevel, loop cut, merge by distance, delete/dissolve, recalculate
normals, mirror, undo/redo, save/load, export OBJ and ASCII FBX.

Everything below is deliberately out of scope for that first release. Items are
grouped by area and marked with the spec phase they belong to.

--------------------------------------------------------------------------------
1. MODELLING TOOLS
--------------------------------------------------------------------------------

[Phase 7] KNIFE TOOL
  Click to cut across faces, snap to vertices, snap to midpoints, Z to cut
  through. The spec's highest-risk item. Needs robust face-plane intersection
  and edge splitting with tolerance handling.

[Phase 7] BISECT
  Plane-based cut with fill and clear-inner/clear-outer options.

[Phase 7] EDGE SLIDE / VERTEX SLIDE
  Constrained sliding along adjacent topology with even and flipped modes.
  The loop-cut ring walk already provides the traversal this needs.

[Phase 4] SPIN / REVOLVE and SCREW
  Revolve a profile around an axis with a step count and angle.

[Phase 4] RIP and SPLIT
  Tear geometry apart along a selection.

[Phase 4] SEPARATE
  By selection and by loose parts. (Join is implemented; separate is not.)

[Phase 4] UN-SUBDIVIDE
  Inverse of subdivide, collapsing a subdivision level.

[Phase 4] GRID FILL
  A true grid fill producing quads. `gridFill` currently emits a triangle fan;
  the quad-grid version needs matched loop pairing.

[Phase 4] PUSH / PULL
  Offset along an averaged normal. `shrinkFatten` covers the common case.

[Phase 4] SYMMETRIZE
  Mirror existing geometry across an axis and weld the seam in one operation.
  Currently achievable via the mirror modifier plus Apply.

[Phase 4] BEVEL — VERTEX BEVEL MODE
  Only edge bevel is implemented.

[Phase 4] BEVEL — TERMINATING FANS
  KNOWN LIMITATION: a bevel terminating against three or more unbeveled edges
  at one vertex can close with a coplanar cap. The result is still a valid
  closed manifold, but carries a zero-volume flap. Common cases (all edges,
  a closed loop, a ring) are correct and tested.

[Phase 4] MERGE — COLLAPSE PER ISLAND
  `collapse` currently behaves as merge-at-centre. True collapse should merge
  each connected selection island separately.

--------------------------------------------------------------------------------
3. TRANSFORMS
--------------------------------------------------------------------------------

[Phase 2] MODAL TRANSFORMS (G / R / S)
  The store has the `ModalTransform` state and the status bar renders its hint,
  but the viewport does not yet drive it from pointer movement. Needs:
    - axis constraint with X / Y / Z
    - axis exclusion with Shift + axis
    - numeric typing for exact values
    - Enter to confirm, Escape to cancel
  Transform via the gizmo and via the properties panel both work today.

[Phase 2] SNAPPING
  Store state and the status-bar indicator exist; the viewport does not yet
  snap. Needs grid increment, vertex, edge and face snapping with a magnet
  toggle.

[Phase 2] PIVOT MODES
  `PivotMode` is in the store and unused by the viewport: median point,
  individual origins, 3D cursor, active element.

[Phase 2] SET ORIGIN TO GEOMETRY / GEOMETRY TO ORIGIN
[Phase 2] PARENTING
  `SceneObject.parentId` exists in the model and serializes, but nothing sets
  it and the outliner does not render a hierarchy.
[Phase 2] 3D CURSOR PLACEMENT BY CLICK
  The cursor is rendered and primitives spawn at it, but it can only be moved
  programmatically.

--------------------------------------------------------------------------------
4. MODIFIERS
--------------------------------------------------------------------------------

[Phase 8] BOOLEAN (union / difference / intersect)
  Stretch goal. Use three-bvh-csg. Do not hand-roll: robust boolean geometry
  is a project of its own.

[Phase 5] MIRROR — BISECT REFINEMENT
  The bisect flag discards faces whose centre crosses the plane. Faces
  straddling the plane should be cut, not dropped.

[Phase 5] SUBDIVISION SURFACE — SEPARATE VIEWPORT / RENDER LEVELS
  One level setting today.

[Phase 5] MODIFIER APPLY FOR LINKED DUPLICATES
  Applying to a shared mesh affects every linked copy without warning.

--------------------------------------------------------------------------------
5. VIEWPORT
--------------------------------------------------------------------------------

[Phase 7] BVH RAYCASTING (three-mesh-bvh)
  Face picking is a linear raycast. Dense meshes need a BVH.

[Phase 7] PREALLOCATED BUFFERS WITH SLACK
  `buildMeshBuffers` reallocates every typed array on each change. The spec
  calls for dirty-flagged partial rebuilds with preallocated slack.

[Phase 1] NUMPAD AXIS VIEWS — FULL SET
  Front/side/top exist. Missing: back, bottom, opposite-side, and the numpad
  ortho toggle.

[Phase 1] CAMERA ROLL RESET binding
  `resetRoll` exists on the controller and is not bound.

[Phase 1] CONFIGURABLE NAVIGATION BINDINGS
  Blender and Maya presets exist; per-binding customisation does not.

[Phase 1] MEASUREMENTS DURING ACTIVE TRANSFORMS
  Depends on modal transforms.

[Phase 1] VERTEX/EDGE/FACE COUNT OVERLAYS IN THE VIEWPORT
  Counts are in the status bar, not drawn in the viewport.

--------------------------------------------------------------------------------
6. MATERIALS
--------------------------------------------------------------------------------

[Phase 5] REMOVE MATERIAL SLOT
  Add, rename-by-colour and assign work; removal does not, because face
  material indices would need remapping.

[Phase 5] SELECT FACES BY MATERIAL

[Phase 1] STATUS BAR COUNTS SHOW THE BASE MESH, NOT THE EVALUATED RESULT
  With an array modifier at count 4 the counts stay at the editable cage's
  numbers. Showing evaluated counts would mean running the whole modifier
  stack on every store update, so it needs a cached evaluation keyed on
  meshVersion + the modifier stack before it can change.

--------------------------------------------------------------------------------
7. FILES AND EXPORT
--------------------------------------------------------------------------------

[Phase 6] BLENDER CI VALIDATION HARNESS
  blender --background --python validate.py
  Import exported fixtures and assert vertex counts, face counts, material
  slots, bounding box, object count and topology integrity. This is what turns
  "does the FBX work?" into an automated test.

[Phase 6] GLTF IMPORT AND EXPORT
  Listed as a secondary format in the spec. Not started.

[Phase 8] BINARY FBX
  ASCII 7.4 is implemented and is what every target engine accepts.

[Phase 6] SMOOTHING GROUPS IN FBX
  Per-vertex normals and smooth/flat shading are exported; explicit smoothing
  groups are not.

[Phase 6] EXPORT SCALE FACTOR AS A SEPARATE CONTROL
  Exposed for custom presets only.

[Phase 2] AUTOSAVE UI
  Autosave to IndexedDB and crash recovery work, but there is no indicator of
  when the last autosave happened and no manual "restore" entry point.

--------------------------------------------------------------------------------
8. UNDO AND COMMANDS
--------------------------------------------------------------------------------

[Phase 3] DELTA-BASED UNDO FOR TRANSFORM DRAGS
  The spec calls for storing only the delta on transform drags. Every step is
  currently a full document snapshot. Correct, but heavier than it needs to be
  for a drag.

[Phase 7] OPERATOR ADJUST PANEL
  `lastOperator` is recorded in the store. A redo-with-new-parameters panel
  (Blender's F9) would let the user tweak an operation after running it.

[Phase 7] window.app.exec GLOBAL
  The operator registry is complete and tested; exposing it on `window` for
  console driving is not done.

--------------------------------------------------------------------------------
9. UI AND KEYMAP
--------------------------------------------------------------------------------

[Phase 7] KEYMAP EDITOR
  The keymap is data (`src/domain/keymap/keymap.ts`) and the overlay renders
  from it, but bindings cannot be edited or persisted.

[Phase 2] OUTLINER HIERARCHY
  Flat list today. Needs nesting, drag-to-reparent and multi-select ranges.

[Phase 4] DELETE / MERGE CONTEXT MENUS
  Blender's X and M open menus; here they run a default or open a dialog.

--------------------------------------------------------------------------------
10. TESTING
--------------------------------------------------------------------------------

DEDICATED TESTS FOR REMAINING PANELS
  Covered directly: every shared component, Outliner, StatusBar, keymap.
  Covered indirectly: TopBar, ToolRail, AddPanel, OperationsPanel,
  ModifierStack, ExportDialog and ShortcutOverlay are all mounted and driven by
  the app shell suite (src/app/App.test.tsx), but have no dedicated tests for
  their own edge cases. PropertiesPanel and MergeDialog are not driven at all.

VIEWPORT AND BRIDGE TESTS
  Viewport, CameraController, picking and ObjectView have no tests. They need
  a WebGL context or a mocked renderer.

END-TO-END BROWSER TEST
  No Playwright or equivalent covering the create → model → export path.

HUSKY + LINT-STAGED PRE-COMMIT HOOKS
  Required by the engineering conventions; not installed because the project
  is not a git repository yet.

--------------------------------------------------------------------------------
11. STRETCH
--------------------------------------------------------------------------------

[Phase 8] TAURI DESKTOP BUILD
  For native file dialogs and a bundled converter. Should not block the web
  release.

[Phase 7] SCULPTING
  Out of scope by design. Proportional editing is the closest approximation
  and is implemented.

TEXTURE PIPELINE
  Explicitly out of scope. Materials are name + base colour, export-oriented
  only. Box-projected UVs are emitted so exports do not break downstream.
